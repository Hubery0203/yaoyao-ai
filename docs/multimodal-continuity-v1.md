# 图文语音衔接与来源保留 V1

修复已有媒体历史在下轮读取时丢失来源的问题，不增加新媒体能力、调用链或自动记忆权限。微信短语音识别、用户发图理解及普通文字仍使用原入口、队列、幂等与用量边界。

## 原问题与行为

图片和语音的USER_MESSAGE已持久化attachment，但loadConversationHistory只返回role/text/time/sequence；后续Core把识别文本渲染为普通User原话，生活事件的只读投影也会重新解析它。后台continuity虽然禁止媒体自动写入长期事实，当前回复仍可能把识别文字当成已确认的近况、住址或偏好。视觉上下文同样丢弃了来源。

现在历史投影只保留允许的image/voice来源枚举，旧文字记录不变。C6和近期对话仍含媒体文字，分别标记为Voice transcript或Image input；角色与原始文字、顺序、收取时间保留。字面User事实证据不使用这些媒体条目。生活投影跳过媒体历史和当前语音，文字更正仍按原规则生效。图片模型的最多6条/每条250字上下文带来源，不携带额外历史、记忆或媒体凭据。

例如语音被识别为“我住在东京”，下一轮问住哪里时不能据此确认住址；明确打字“我现在住在大阪”仍可作为新的原话证据。普通语音接话不要求每句重打字；只禁止把识别直接升级为已确认事实。先前图片的助手描述仍可供话题衔接，但不声称能重新看旧图像素。

## 验证与边界

增加实际持久化来源/顺序、隔离、当前请求排除、媒体不写长期事实、文字更正与回放、Core实际模型上下文等回归。历史格式中来源标签属于内部模型上下文，不作为用户可见解释尾句。

不修改历史事件、不迁移数据库、不重新识别旧媒体、不扩大配额、不改变音色/主动联系或照片参考。不增加后台任务、依赖、端口或资源限额。保持已完成请求优先回放，兼容上一版直接回退。

本地检查与模拟不能证明真实模型每次都遵从来源边界；有限真实模型检查和手机混合聊天反馈应分别记录，不用测试数量代替体验验收。006C和网页仍暂缓。
