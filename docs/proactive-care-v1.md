# 主动陪伴：一次性关心事项 V1

本人确认一个主题和时间，遥遥在合适的联系窗口发一次简短关心。第一版用确定性文案和已有队列，不调用聊天/语音/图片模型，不从普通聊天自动创建任务，也不推断事项已经完成。

## 使用

主动联系需已由本人开启。发送：

```
添加关心：明天 18:00 | 面试
```

核对主题、账号联系时区和时间后，10分钟内发送预览中的 `确认联系 XXXXXXXX`；也可 `取消联系 XXXXXXXX`。预览不会创建任务或开启主动联系；只有当前绑定账号的实际文字消息能操作。语音中的这些命令会要求打字确认。

`关心列表` 显示当前账号最近25条关心记录，`结束关心 编号` 或 `取消关心 编号` 取消尚未进入发送边界的事项。发送结果未知时仍可正常聊天和查看列表；明确结束该项会停止等待、保留原错误/确认/尝试及额度记录，不能撤回已发出的消息。`关心帮助` 查看范围。取消关心与取消提醒使用独立的记录类型，不能靠相同编号后缀误操作另一类记录。

主题最多40字，规范化空白和全角字符；最多3件待关心事项，同一待办主题不重复添加。与提醒共用最多20条待办。已经发送后，只有本人再次明确添加并确认才会新建；没有不回复后的自动催问或循环计划。

## 联系边界

- 只在约定时间之后30分钟内尝试联系，错过就过期；重启不补发旧窗口。排队后再次检查截止时间，不能把新排队时间当作新的宽限期。
- 沿用现有主动联系总开关、本人联系时区、免打扰、停聊至少10分钟和微信会话24小时边界。每日与滚动24小时共用原1次或2次上限，不增加额度。到期提醒优先，其次关心，再次已有问候。
- 用户新消息优先，会跳过尚未发送的主动消息。暂停/关闭主动联系、通道暂停/授权失效、设置改变和取消都在发送边界重新检查。
- 发送中断或结果未知保持 uncertain，不自动重发，也不释放已尝试的联系额度；不会堵住后续正常聊天。本人明确结束后标记为跳过，并在错误字段保留原结果，不视作送达确认。显示“接口已接受”不等于手机实际收取确认。
- 关心仍通过原主动联系文字通道，不调用 TTS。当前已选音色和日常聊天语音开关不因这一功能改变。

示例文案：`想听你说说「面试」这件事。` 主题作为用户明确允许的字面内容，不执行其中的命令，也不声称“面试已经结束/顺利通过”。不根据计划日期自动安排联系或虚构生活事实。收到普通回复后由既有 Core 接话；已接受主动消息只记为 assistant 历史，不伪造 user 消息或自动生成记忆任务。

## 持久化和隔离

迁移0017给已有 `weixin_followups` 新增 `kind`（旧记录默认 reminder）、`care_topic` 两列及部分索引，无新表/依赖/后台进程。care 记录必须有主题，reminder 不允许附带主题；继承原通道强制 RLS。

关心预览、绑定账号校验、设置版本检查、待办上限、去重、任务建立和持久化控制回执在同一通道锁事务中提交。重启或确认回放只读原回执，不再创建任务。调度与发送前都检查当前绑定所有者；旧绑定记录不能投递给新账号。
