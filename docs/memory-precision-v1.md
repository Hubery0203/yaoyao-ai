# 记忆提升第一轮：检索与事实边界

## 用户可见结果

- 问一个具体旧偏好时，相关记录不会仅因重要度较低而被前 50 条无关记录挡住。
- “我住哪里 / 我叫什么 / 喜欢喝什么”等回忆问题按所问类别找候选。
- 待核实的地点或偏好不能覆盖同槽已确认事实；只有已确认更正才沿 supersedes 链替代旧记录。两条独立已确认矛盾记录仍按不确定处理，不按新旧猜。
- “今天不喝 / 这会儿不想喝 / 此刻不吃 / 这一次不喝”等只影响当前回复中的推荐背景，不永久改写偏好；引用、假设、问题不成为限制。

## 实现与边界

SQL 在 LIMIT 前对最多 16 个参数化字面词做匹配；相关的 CONSOLIDATED 记录优先于相关的 VALIDATED 记录。中文使用二字片段，类别型回忆补充少量固定词。% 和 _ 不作为通配符，账号及遥遥归属过滤和 RLS 不变。最终仍由纯函数排序、冲突检查及摘要投影决定入选内容，默认候选 50 条、输出 5 条不变。

不新增嵌入/模型层、不修改提取策略 memory-v2-explicit，不重放旧候选、不重写已有记忆、不改审计与确认流程、无数据库迁移。

这不是任意自然语言都能记住的提取升级。数据库仍需在同账号可检索记录上判断词匹配，候选上限不代表只扫描 50 条；大规模账号需要另行评估索引及查询时间。16 个词及 50 条候选之外不保证召回全部相关内容或发现全部冲突。语义近义词不保证匹配，日期不明的旧临时限制不会被当成今天仍有效。长期事实、近期计划与事项完成仍沿用现有边界。

## 验证

定向数据库场景：65 条无关高重要度记录不能遮挡目标偏好；一条候选预算仍能找地址；待核实高分新地址不挤掉已确认地址；恶意查询片段不能扩大账号范围，空词查询可执行。

新增纯函数及运行时场景：独立矛盾、确认更正链、未确认 supersedes、临时限制、引用/假设/问题、不修改原上下文。

六个模拟产品场景在同一 ConversationOrchestrator 中注入合成长期记录，使用真实排序/投影函数。此模拟不替代 SQL 集成验证或真实模型语气审阅；没有传入真实用户聊天。

本地最终验证：909 项单元与合同、3 项 e2e、266 项 PostgreSQL 集成，共 1,178 项通过。48 个既有/新增模拟产品场景通过规则与回放检查。完整集成曾出现一次提醒取消接口 404/409 结果差异；单独和完整复核均通过，未改动该功能或放宽断言，偶发原因尚未确定。私有失败及复核日志已保留。
