# MVP-009 A–D — Weixin controls, natural conversation and recoverability

Implementation scope following deployed 009E. 006C stays on hold. No new public website, proactive-contact opt-in, proxy change or image API test. Paid text evaluation and VPS release need the existing scoped owner approval.

A: owner preference list/help plus exact single-setting commands and narrow persistent natural phrases, all writes previewed and confirmed. Commands for nickname, reply length, affection, questions, advice and timezone; optimistic version checks and durable history/replay. A temporary chat request does not change defaults.
B: recent-life list/help/create/update using explicit records and stable random suffix references. Preview before confirming a completion/cancellation/reschedule, reject ambiguous references and changed records; capture dates/timezones at request receipt and fresh confirmation sequence. Does not create long-term memories or outreach.
C: current-turn and history-aware concise speech guidance, repair gates for observed repetitive openings and mechanical commentary, with multi-turn regressions. Preserve helpful detailed answers, care and supported uncertainty. Do not hard-code every casual reply or hide unsafe raw output behind a postprocessing shortcut.
D: bounded numerical rolling telemetry and lower hot-path logging/retention overhead. An authenticated encrypted streaming backup/restore tool with private key, manifest, limits and isolated staging; explicit destination is deferred by owner, so no external upload, scheduled task or real restore is performed. Prove recovery against a disposable PostgreSQL database and retain live state.

Forward migration 0010 for owner-scoped pending companion command actions; existing preferences, life events and command replay storage are reused. New command namespaces separate their confirmations from memory confirmations. Release preserves all current data and photo state, ports/resource limits/binding/cutoff/cursor. Existing photo key and reference never enter version control or telemetry.

## Owner commands

- `设置列表` / `设置帮助`; `设置称呼：小雨`, `设置回复：简短|自然|详细`, `设置亲昵：自然|克制`, `设置追问：少问|自然`, `设置建议：按需|自然`, `设置时区：Asia/Tokyo`, `恢复默认设置`.
- Narrow persistent natural phrases: `以后简短一点`, `以后不要追问了`, `以后不要给我建议`, `以后叫我小雨`. Only exact standalone phrases persist after confirmation. `这次简短一点` remains a current-turn request.
- Writes preview only changed settings; `确认设置 ABC123` / `取消设置 ABC123`, within ten minutes. New preview invalidates the older companion preview, independent from memory confirmation codes. Settings changed elsewhere invalidate the expected version.
- `近况列表` / `近况帮助`; `记录近况：我明天要面试`; `更新近况 XXXXXXXX：完成|取消|开始|改到明天|延期到后天`. Eight-character references use random ID suffixes. Same-subject ambiguity requires the exact reference. Literal recent-life grammar remains the recognized 008 subject set; unsupported statements return help rather than silently guessing.
- `确认近况 ABC123` / `取消近况 ABC123`. Relative dates are resolved at preview receipt in the account timezone. A changed target/version/timezone or changed same-subject snapshot invalidates confirmation. Successful change uses the confirmation user-event sequence so queued old statements cannot revert it. Expiry is not an inferred outcome. Recent list shows the newest ten retained records with expiry labels.

No new editor for CORE memories, permanent history deletion, autonomous preferences, outreach or arbitrary natural-language tools is added. Control history is visible as operation status and excluded from life/memory inference.

## Naturalness and resources

The original full response is validated before delivery. Narrow casual-only gates cover mechanical emotion commentary, service tails and a third repeated substantial opening among recent assistant replies. Explicit repetition, short affectionate closings, care and detailed tasks are preserved. Repair remains bounded; no new silent casual-response projection. The extra bounded guidance is counted in context overhead. Multi-turn synthetic fixtures extend the existing evaluator; mock success still leaves human tone review pending.

Performance logging changes from one performance log per turn to bounded per-process 15-minute windows, normally emitting every ten records or on the next record after one minute. Failure metadata emits promptly. Generation/replay counts are separate; mean generation latency and histogram p95 upper bound are numerical summaries, not exact percentiles. Only known successful token usage and provider attempt counters are accumulated; no currency/billing total is claimed. Counters reset on process restart; quiet processes do not run a reporting timer. Quality logs remain available. No user content, model text, IDs, keys or arbitrary telemetry fields are retained by the aggregator.

`deploy/vps-lite/resource-report.py` is a read-only optional numerical snapshot. `tools/backup` ships with Linux release/code artifacts, but does not run, create keys, schedule tasks or upload data automatically. The owner chose to defer the offsite destination. The real local encrypted-backup drill restores a custom-format PostgreSQL dump into a NEW disposable database and compares all table counts/hashes and RLS, not a live server or bare-machine recovery. Key management and transfer destination remain operator tasks.
