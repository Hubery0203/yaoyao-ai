# MVP-010 A/B — 微信多轮接话与主动联系管理

开发范围：009A–E之后，006C继续搁置。只开发和本地验证；真实模型调用、GitHub上传/CI与东京发布另列具体评估，未获本轮批准不执行。

A：合并短消息视为同一轮；最新话题优先，短回答可承接最近明确问题，但独立新分享不被当作旧问题答案。日常回复不机械复述整个合并输入，不在用户明确拒绝后重提已撤销建议。保留安静陪伴、简短亲昵、详细求助和引用/写作语义。窄规则修复仍有次数上限，不截断普通回复。新增多轮合成场景和规则/回放检查；mock不能代表自然度通过。

B：复用007的额度、会话、暂停、发送边界和防重发调度。微信独立命令“主动联系状态”“提醒列表”“联系帮助”；开启主动联系、免打扰、联系时区、每日上限、问候设置和新增提醒均先预览，十分钟内“确认联系 CODE”生效，“取消联系 CODE”放弃。精确“关闭主动联系/暂停主动联系”等立即关闭，不要求二次确认；不暂停整个收件通道，以便本人用微信重新开启。

提醒格式“添加提醒：明天 09:00 | 记得带伞”（也支持今天/后天/YYYY-MM-DD）；按联系时区计算。只接收未来30天、1–120字，最多20个待办；夏令时不存在/重复墙钟时间拒绝猜测。列表显示编号、时间、状态，不把接口接受说成送达。“取消提醒 编号”立即取消可安全撤销的项目；进入发送边界则明确不能撤回，不重发。开启不保证准点：沿用安静时段、至少停聊10分钟、最近24小时会话上下文、额度及微信接口限制。

新增0011一张通道RLS指令表：保存原文/确定性回复、预览、随机码、期满及预期设置版本。操作与回复同通道事务提交，来源入站行和当前绑定本人双核对。重放同key返回原回复，不二次创建提醒；同key异文拒绝。新预览取消旧预览；设置变动使旧确认失效，提醒确认再次检查时间/额度/启用。控制消息独立成组，不进入模型/个人记忆提取。

验证门槛：编译、lint、边界、现有单元/合同/集成/端到端、加密备份和mock评测；真实PG测试覆盖RLS、跨账号、预览确认/取消/过期/CAS、事务回放、批次隔离、停用和提醒发送边界。东京/代理/图片配置均不在开发变更范围，不代本人开启主动联系。

本地交付：997项检查通过，详见 docs/releases/010/eval-summary.md。提醒列表优先展示待办及未确定投递，最多25条，长内容以省略号缩略；不会把已接受的旧提醒排在待办前。停止命令沿用既有立即停用路径，不暂停收件；可用“主动联系状态”核对。

### 受限真实检查修订

首次12场景/15次请求未发布：换话题后的多行分享、已回答的短选择和拒绝建议后仍有多余追问；完成分享“先缓一缓”也需遵守按需建议。修订将短答案与最后明确问题中的原词对齐，仅对已对齐选择收住追问，歧义短句和必要支持仍可澄清；合并分享覆盖首/末行，完成和普通分享不附休息安排。详细求助区分渐近量级与精确上界。二分场景词汇检查允许“中点/中间/中部”同义表达，不能据匹配某个词声称事实审阅通过。剩余9次请求仅修复原场景，不扩展新场景。
