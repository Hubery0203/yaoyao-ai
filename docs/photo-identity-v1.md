# 照片形象一致性 V1

## 范围

以本人选定的原自拍为唯一参考；不替换、裁剪、压缩或加工原文件，不把生成结果再次作为参考。只改善请求约束及参考来源保护，不宣称已解决模型的脸部漂移。

当前生成链为 MiniMax CN / image-01，一次一张、base64 输入输出，保留 AI 标识、水印、滚动24小时上限、失败/未知不自动重试和发送幂等。

## 改动

- 新 PHOTO_REFERENCE_SHA256 必须与私有参考文件实际字节一致，才能启用照片。空配置视为未配置，错误格式拒绝配置，指纹不匹配在占用任务额度前停止。
- 提示词以参考图决定脸部比例、眼睛形状与间距、鼻唇、发际线和头发，不再用“二十多岁”等泛化年龄描述替代；场景只提供服装、背景和姿态变化。默认竖版3:4，强调自然透视、清晰可辨的面部，不夸大眼睛、收窄下颌或添加过度美颜。
- 1500字符请求上限及控制字符检查在付费任务预留前执行。旧生成/上传恢复仍不重新出图。
- 普通照片不固定 seed，保留变化。操作员验收可用受限整数种子比较两个场景；种子帮助复现，不保证锁脸，不作为质量评分。
- 没有新增依赖、数据库字段、端口、定时任务或自动人脸识别。

## 配置与回退

将参考文件 SHA256 私存于 PHOTO_REFERENCE_SHA256。只从本人批准的原始文件计算，不从本次生成结果计算。参考及目录仍要求0600/0700，禁止软链接文件；示例配置见 .env.example。

发布必须同时安装新代码和该配置，否则照片会显示配置不可用；聊天/语音不需要该值。新增配置为非密钥指纹，不改变已有图片、语音、DeepSeek密钥。先保存私有配置原件，失败时恢复配置及上一版本，不回滚业务数据。

## 验收工具

先编译，再执行默认 dry-run（无API请求、无需密钥）：

```
node scripts/evaluate-photo-identity.mjs --reference /absolute/private/original.png --sha256 APPROVED_SHA256
```

真实检查必须先取得明确费用许可：提供私有 MINIMAX_IMAGE_API_KEY、MINIMAX_IMAGE_REGION，并使用 --live --max-calls 2 --out /absolute/private/check-directory。工具要求干净源码树，默认种子20261027，两个候选场景各一张。run.lock在首次请求前持久落盘，ledger在每次调用前记录started并同步。失败或结果不明即停止，不自动重试、不删除锁重跑、不在新目录绕过本轮预算。输出及账本0700/0600，不打印图像base64或密钥，不向微信发送，不写生产任务表。

两个场景为书桌自然自拍、窗边米色针织衫半身自拍。预览用原图直接对照五官比例、脸型、头发、整体气质；不使用自动“相似度百分比”冒充人工认可。若本人不认可，不发布、不换参考源、不擅自追加出图。

## 验证与限制

本地946项单元/合同/e2e、266项PostgreSQL集成，共1212项检查通过，新增15项照片检查。初次并发执行中健康及体验接口各出现一次socket hang up，顺序完整复核均通过，未放宽断言、未改对应接口，偶发原因未确认。原失败及复核日志留在私有工作区。

所有测试均为固定数据或dry-run，尚无本轮真实图片。字节指纹只证明参考来源，不证明脸相同；提示词及构图只是待验证策略。MiniMax仍可能改变五官、年龄观感、发型、姿势或细节。官方参数未提供本实现可使用的强制锁脸开关，不能虚构face_weight参数。

来源（2026-10-27核对）：[MiniMax图生图](https://platform.minimax.cn/docs/api-reference/image-generation-i2i)、[MiniMax文生图参数](https://platform.minimax.cn/docs/api-reference/image-generation-t2i)。接口支持人物参考、3:4、seed；相同seed和参数用于生成相近内容，不是身份一致性保证。
