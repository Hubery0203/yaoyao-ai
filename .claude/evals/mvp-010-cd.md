# 010C/D acceptance gates

C: explicit status/help does not reserve, call an LLM/image provider, consume quota or extract memory. Owner/channel RLS; status distinguishes failed generation, saved artifact, interface acceptance and uncertain delivery. Bounded provider failure parsing persists only allowlisted codes, never body/prompt/key. Known credit failure and restart replay do not authorize another generation. Existing photo reservation, cancel, retry-upload, size/origin and memory-boundary checks remain green. Live image consistency and actual mobile receipt require scoped approval and real results.

D: encrypted archive only; explicit private config and separate key; upload no overwrite; full downloaded hash and GCM/manifest verification before successful receipt. Unknown/failed transfer and malformed/tampered/oversize archives never trigger retention. Retention touches only initialized repository namespace and keeps at least two backups including verified newest. Replays recover safely, no secret output, no shell-option injection, symlinks/path traversal refused, unknown SSH host keys fail closed. Restore only new private paths/isolated DB, never production; no receiver during drills. Fake storage tests do not count as offsite recovery.
